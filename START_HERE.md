# Задание для GPT-6.1-sol Ultra

Ниже готовый промпт для запуска реализации после переключения модели. Папка проекта: `~/Code/app-transfer`.

---

Реализуй MVP App Transfer в этой папке. Концепция и дизайн уже утверждены мной; заново discovery и выбор дизайна не нужны.

Сначала прочитай `AGENTS.md`, `README.md`, `PRODUCT.md`, `DESIGN.md`, `docs/ARCHITECTURE.md`, `research/FINDINGS.md` и `IMPLEMENTATION_PLAN.md`. Открой `prototypes/approved-glass.html`, посмотри скриншоты в `prototypes/screenshots/`. Выполняй план последовательно, отмечая проверенный прогресс и блокеры в `STATUS.md`.

Нужен настоящий нативный macOS app на Swift/SwiftUI для Apple Silicon/macOS 15+. Упаковка в самостоятельный DMG входит в MVP. Платное Apple Developer Program и notarization не нужны; глобально отключать Gatekeeper нельзя. У конечного пользователя не должно быть зависимостей от Terminal, Homebrew, iMazing или отдельно установленного ipatool.

Архитектура: прямой libimobiledevice через узкий C-мост для телефонов; bundled Go helper на pinned ядре ipatool для GUI Apple Account/2FA и скачивания. Не переписывай App Store-протокол и не превращай HTML-прототип в WebView-приложение. Проверяй clean login и полный реальный transfer-flow до финальной полировки.

Интерфейс: скрываемая общая библиотека слева (`⌘S`), любое число равноправных колонок телефонов, горизонтальная прокрутка при нехватке места, скрываемая очередь снизу, журнал, аккаунты, настройки. Телефон → библиотека только скачивает; телефон → телефон скачивает при необходимости и устанавливает; библиотека → телефон устанавливает сохранённое. Никаких постоянных ролей «откуда/куда» и лимита в два устройства.

Сохрани утверждённый спокойный frosted-дизайн и обе темы. Компактные списки по умолчанию; в настройках язык RU/EN, плотность и тема. Настройки/аккаунты закрываются при клике снаружи, включая другое приложение, по Escape и при открытии другого popover. Это не отменяет фоновые задачи.

Удаление IPA из библиотеки обязательно: явное действие/подтверждение, перенос в Корзину Mac, защита используемых очередью файлов, без удаления телефонных приложений. Удаление с телефона опционально, отдельный этап с подтверждением конкретного устройства и риска потери данных; не задерживай основной MVP ради него.

Перенос банковских сессий и локальных данных не входит в scope. Не обещай скачивание только по факту наличия приложения на телефоне. Успех установки подтверждай readback bundle/version, запуск проверяй отдельно. Не удаляй существующие приложения ради исправления установки.

Работай автономно в локальном проекте, не останавливайся после плана или mock UI. Обычные обратимые решения, сборка и необходимые проверки входят в задачу. Запрашивай действие только там, где действительно нужны отсутствующие устройство, unlock/trust, секретный ввод в GUI или конкретная авторизация на live изменение телефона; учитывай уже выданные разрешения, не спрашивай повторно. Пароли/2FA не запрашивай в чате. При внешнем блокере продолжай независимые части.

Не публикуй GitHub repository/release, не делай commit/push и не удаляй пользовательские приложения без соответствующего отдельного разрешения. Не копируй реальные IPA/credentials/inventory в исходники.

В конце передай `.app` и `.dmg`, команды воспроизводимой сборки, итоги `docs/ACCEPTANCE.md` и точный список ограничений. Разделяй подтверждённое на mock/local/live-device/clean-user уровнях. Если live-условие недоступно, честно пометь preview и pending check, не симулируй завершение.
